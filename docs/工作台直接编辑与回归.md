# 工作台直接编辑与保存前回归

BILE Workbench 的直接编辑模式用于修改 **BILE v4 中已经通过样本验证的字段**。它不会在输入过程中覆盖原始 BIN；每一次“应用到暂存预览”都会将完整待提交补丁写入临时文件，重新解析 BILE，并以该临时文档渲染预览。只有用户显式导出补丁 JSON 或在后续流程中应用 JSON，才会产生可带走的文件。

## 可直接编辑的字段

| 编辑对象 | 工作台位置 | 可改字段 | 作用 | 安全边界 |
|---|---|---|---|---|
| `BELE` 关键帧 | 选中动画，定位槽位，右侧检查器 | `xx`、`xy`、`yx`、`yy`、`x`、`y`、Alpha、`initial_phase` | 二维仿射变换、ARGB 透明度，以及实际嵌套子动画段的初始槽位。 | 不改变关键帧、轨道、帧或通道数量；`initial_phase` 必须落在所引用子动画的帧范围内。 |
| `BMTI` 图片元素 | 选中精灵，右侧检查器 | 锚点 X、锚点 Y | 改变精灵在局部坐标中的旋转/缩放中心。 | 不改变元素类型、名称长度或字符串区。 |

> 当前槽位可能同时激活多条轨道。检查器会默认加载第一条活动轨道的 BELE 编号，并显示其余活动轨道数。需要修改另一条轨道时，请直接输入对应的 BELE 索引，或先通过导出的完整 AI 中转 JSON 确认轨道映射。
>
> `playback_mode` 目前仅显示、不允许写入。原包虽观察到 0/1/2，但 1/2 在当前样本全部落在静态精灵轨道，尚无证据证明它们是可安全编辑的子动画播放控制。

## 推荐操作流程

| 步骤 | 操作 | 目的 |
|---:|---|---|
| 1 | 打开 BIN；确认同名 XML 和 WebP/PNG 被自动绑定。 | 先执行完整结构校验。 |
| 2 | 在资源树中选择动画，使用底部时间线或槽位滑块定位。 | 将预览定位到待调整的时间点。 |
| 3 | 在检查器修改矩阵、平移、Alpha 或 `initial_phase`，然后点击“应用关键帧到暂存预览”。 | 生成内存补丁并重新解析。 |
| 4 | 使用“撤销”或“重做”比较多个方案。 | 编辑历史仅影响暂存会话。 |
| 5 | 使用“导出当前槽位对比图”。 | 输出左侧原始帧、右侧暂存帧的 PNG 供人工检查。 |
| 6 | 使用“导出待提交补丁”。 | 先执行保存前预检：源 SHA-256、完整重解析、引用图和 `initial_phase` 对应子动画帧范围均须通过。 |
| 7 | 在新文件上应用补丁并在原游戏中回归。 | 工作台结构验证不能代替游戏运行时验证。 |

## 画布优先的图片元素热点编辑

选择图片元素后，中央画布会直接渲染对应图集区域，并显示带十字线的“热点”句柄。热点坐标按照已验证的 BMTI 与图集 `refx/refy` 关系换算；拖动过程中只更新检查器中的坐标显示，不会在每个鼠标移动事件上生成候选 BIN 或触发完整重解析。

松开鼠标后，工作台才通过既有的 `SetAnchorCommand` 提交一次暂存编辑，并重新解析暂存文档验证结果。用户仍可以在检查器中精确输入坐标，画布上的热点会同步更新；动画元素则继续使用原有槽位、Track 和 BELE 编辑路径。画布适配优先关注实际非背景内容，窗口 resize 或用户已经手动缩放后不会反复把视角强行缩回小预览。

## 补丁和撤销模型

编辑会话的补丁以输入 BIN 的 SHA-256 为锚点。补丁不能应用到字节内容不同的 BIN，因此能避免将“同名但不同版本”的动画错误覆盖。撤销与重做使用会话内快照；每次恢复后都会重新生成临时 BIN 并执行完整解码。

在导出补丁前，工作台会再次应用完整待提交变更到临时 BIN 并重解析；若发现动画引用环、结构错误，或 `initial_phase` 超出某条真实子动画引用的帧数，导出会被阻止。若某个 `initial_phase` 所在 BELE 当前没有子动画目标，工作台会发出警告但允许用户将其作为实验性数据保存。

```text
原 BIN（只读）
    ↓
编辑会话：关键帧 / 锚点补丁 + Undo / Redo
    ↓
临时 patch.json → 临时 preview.bin
    ↓
BILE 完整重解析 → WebP/XML 合成预览 → 原始/暂存对比 PNG
    ↓
用户显式导出 patch.json（最终仍需游戏内回归）
```

## 当前不开放的结构性编辑

新增/删除关键帧、轨道、帧、通道、元素以及变长改名，都可能改变 `BELE/BXDI/BMRF/BYAL/BMTI/BRTS` 的记录数、块长度和累计消费关系，因此默认不开放。这样的功能应在“完整重建模式”中实现，并以最小新动画的游戏内验证为前提。
