# BILE Workbench 专业轨道编辑与取证指南

**版本：** 1.0  
**适用范围：** BILE v3/v4 的保守编辑，以及 BILE v2 的只读轨道审阅。  
**目标：** 将工作台作为 BILE 动画的专业“理解—编辑—验证—取证”瑞士军刀，而不是批量流水线或通用骨骼动画软件。

## 一、定位

BILE Workbench 的重点不是一次性处理大量资源，而是对一个复杂动画三件套进行可追溯的专业处理。每一次变更都应能回答四个问题：**改了哪个 BELE？它在原始文档中被哪些轨道引用？离线画面发生了什么变化？游戏内是否得到同方向证据？**

成熟动画工具通常将 Dopesheet 的关键时刻概览和属性/数值上下文分开，同时令它们共享选择状态。[1] [2] BILE Workbench 借鉴这种工作流组织，但不将 BILE 伪装成连续曲线系统：BILE 的当前实证模型是**离散槽位、通道、保持段、Track 与 BELE 记录**。

> **核心原则：** 轨道表和影响范围报告描述的是已解析文档中的静态引用关系；它们不能替代游戏内运行时结论。

| 层级 | BILE 工作台的术语 | 已验证作用 |
|---|---|---|
| 动画根 | BMTI 动画元素 | 含帧范围和多个通道；可作为预览、时间线和实验目标。 |
| 通道 | Channel | 以离散 Frame 序列描述一组时间轨道。 |
| 保持段 | 当前 Frame 到下一 Frame 前一槽位 | 当前 Frame 内的 Track 会在该范围内持续生效。 |
| Track | `keyframe_index → element_index` | 将一个 BELE 变换/颜色/相位记录作用到精灵或子动画目标。 |
| BELE | 关键帧记录 | v3/v4 已验证可保守编辑仿射矩阵、ARGB、`initial_phase`；`playback_mode` 只读。 |

## 二、专业编辑标准流程

| 步骤 | 工作台操作 | 产生的可审阅信息 | 不能据此断言的内容 |
|---|---|---|---|
| 1. 选择动画根 | 在“动画”Dock 选择根动画。 | 槽位数、通道数、当前文档状态。 | 游戏地图中的单位人数或外层阵列数量。 |
| 2. 定位槽位 | 滑块、键盘方向键或时间线点击。 | 画布帧、当前槽位、活动 Track 表。 | 每条 Track 都独立对应一个游戏单位。 |
| 3. 选择轨道 | 点击时间线通道，或在“轨道检查器”选择一行。 | 动画根/通道/保持段/Track/BELE/目标元素完整链路。 | 该 BELE 只在当前动画生效。 |
| 4. 审阅字段 | 检查器加载被选 BELE；确认矩阵、ARGB、`initial_phase` 与只读播放模式。 | 当前命令会修改的白名单字段。 | 未显示字段可安全写回。 |
| 5. 暂存编辑 | 应用关键帧或锚点编辑。 | 内存候选 BIN 完整重解析、撤销/重做、文档状态条。 | 原始 BIN 已被修改。 |
| 6. 局部取证 | 使用“导出 BELE 轨道影响范围”。 | 每个被改 BELE 的静态引用表（动画根、通道、保持段、目标）。 | 运行时一定同时显示所有静态引用。 |
| 7. 视觉差异 | 导出当前槽位对比图或候选动画差异报告。 | 像素热区、可见变化槽位和保守字段差异。 | 游戏内渲染一定完全一致。 |
| 8. 游戏内回归 | 创建实验包/回归案例，登记截图、录屏或日志。 | 候选哈希、固定变量、证据文件和结论状态。 | 未登记证据的假设已被确认。 |

## 三、轨道检查器的使用

轨道检查器会列出当前槽位每条活动 Track。列的含义如下。

| 列 | 含义 | 审阅建议 |
|---|---|---|
| 通道 | `通道 N · Track M` | 同一通道在同一 Frame 可有多条 Track；不要将通道编号当作单位编号。 |
| 保持段 | 当前 Frame 的起始槽位至下一 Frame 前一槽位 | 用于判断某 BELE 在哪些离散槽位保持有效。 |
| BELE | 实际被 Track 引用的关键帧索引 | 这是 v3/v4 关键帧编辑与影响范围报告的主键。 |
| 目标 | Track 指向的 BMTI 名称 | 精灵目标与子动画目标的渲染意义不同。 |
| 类型 | 精灵或子动画 | 子动画还会经历已验证的嵌套时钟与 `initial_phase` 行为。 |

选择某一行后，时间线会高亮对应通道和关键帧起点；检查器会加载同一 BELE；状态栏会显示完整引用路径。槽位切换会清除轨道选择，避免把旧槽位的 Track 上下文误用于新槽位。

## 四、轨道影响范围报告

“导出 BELE 轨道影响范围”会在所选目录写入：

| 文件 | 内容 |
|---|---|
| `track_impact.json` | 可供脚本、AI 中转审计或回归工具读取的结构化静态引用表。 |
| `track_impact.md` | 适合人工审阅的 BELE → 动画根/通道/保持段/Track/目标表。 |

报告只处理**当前暂存补丁中实际存在的 BELE 编辑索引**。BMTI 锚点编辑不使用该表，因为它的影响关系是元素引用层面而非 BELE Track 引用层面。报告可与候选像素差异、实验包清单和游戏内回归案例一起保存。

## 五、严格边界

| 能力 | 状态 | 原因 |
|---|---|---|
| v3/v4 BELE 仿射矩阵、ARGB、`initial_phase` 暂存编辑 | 支持 | 已有补丁白名单、完整重解析和跨游戏回归。 |
| v3/v4 BMTI 锚点暂存编辑 | 支持 | 已有保守写回与图集渲染验证。 |
| `playback_mode` 写回 | 禁止 | 结构性使用已观察到，但缺少运行时扰动实验。 |
| BILE v2 写回 | 禁止 | 五节容器可读可预览，但字段写回语义尚未实证。 |
| 新增/删除/重排 Frame、Track、元素、字符串或节 | 禁止 | 块布局、计数、偏移和游戏兼容性尚无充分重建实证。 |
| 静态引用范围直接等同游戏内人数 | 禁止 | 外层编队/阵列和引擎实例化仍是独立运行时层。 |
