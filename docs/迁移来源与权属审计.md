## 4. 本次迁移范围

本轮实际落地：

- RawBileImage：保存完整原始字节、Section Header、Section Payload 和 SHA-256。
- BileMutationBuffer：固定长度字段覆盖，并记录预期 changed-byte offsets。
- Candidate Gate：重新解析候选，验证文件长度、版本、Section 顺序、计数、Header 和实际字节变化集合。
- Transactional Publish：同目录临时文件、fsync、回读校验、源哈希复核、默认 no-overwrite、显式覆盖备份与失败恢复。
- Expected-old：新生成补丁记录旧值；旧版 v1 补丁继续通过 source SHA-256 兼容。
- 独立合成 BILE 测试：不依赖或分发原版游戏样本。

## 5. 明确不迁移的内容

- WC4 专属 OriginalAnimationAssetLoader、FormationAnimationPlayer、Army/Unit 绑定和配置语义。
- WC4 WPF UI、.NET Runtime、WC4 资产、SO/APK 工具或任何 WC4 构建依赖。
- 来源报告中对 WC4 1.28.0 的游戏内行为结论，除非另行验证其对目标 EasyTech 游戏版本成立。
- Spine 3.8/4.1 研究不属于本次 WC4 来源迁移；它仍以 BILE Workbench 自身代码和证据为准。

## 6. 后续来源治理规则

每次新增迁移都必须记录来源仓库、完整 commit、文件路径、文件 SHA-256、采用的事实、代码是否直接复制、目标许可证和被排除的资源。不能将来源报告中的历史测试数字写成当前 Python 仓库已经重新通过的测试结果。
