# 动画序列导出与游戏内实验包

BILE Workbench 现在可以把已解析的 BILE v4 三件套导出为**完整动画序列**，并将当前暂存修改组织为一个可用于原游戏人工回归的实验包。两者服务于不同目标：序列导出用于观察和社区展示；实验包用于验证修改后的 BIN 能否被目标游戏加载。

## 完整动画序列导出

在资源树中选择一个**动画元素**后，使用“编辑 → 导出完整动画序列”。工作台会按该动画的整数槽位从 `0` 渲染至 `frame_count - 1`，采用当前的 `reference_v4` 嵌套时钟、XML 图集裁切、`refx/refy` 参考点、BELE 仿射和父色相乘规则。

| 格式 | 输出内容 | 典型用途 | 默认背景 |
|---|---|---|---|
| GIF | 单个循环 GIF | 快速分享、群聊演示、肉眼检查。 | 深色不透明。 |
| APNG | 单个循环 PNG 动画 | 透明背景效果、网页或需要更好颜色表现的展示。 | 透明。 |
| PNG 序列 | 每个槽位一个 PNG 加 JSON 清单 | 逐帧对比、视频合成、精确回归。 | 深色不透明，除非调用底层接口。 |

每次导出都会同时写出 `*.manifest.json`，其中固定记录动画名、槽位范围、帧数、FPS、画布尺寸、嵌套时钟模式和输出文件名。默认画布为 `512×384`，导出器限制单次不超过 240 帧和 1,048,576 像素/帧，以避免高分辨率资源导致内存失控。需要完整高清导出时，可通过 Python 接口分段提高画布尺寸。

> GIF/APNG 是**离线预览结果**，不代表游戏原生播放格式，也不会修改任何 BIN、XML 或 WebP。

## 游戏内实验包

完成至少一项暂存编辑后，使用“文件 → 生成游戏内实验包”。该操作会先执行保存前预检，再把候选 BIN 放入一个 ZIP。候选 BIN 在 ZIP 内会恢复为原 BIN 的文件名，因此可在备份后直接用于资源替换。

| 包内路径 | 内容 | 用途 |
|---|---|---|
| `replace_after_backup/<原名>.bin` | 当前暂存修改实体化的候选 BIN。 | 替换前先备份游戏中的同名 BIN。 |
| `replace_after_backup/<原名>.xml` | 原三件套 XML。 | 与候选 BIN 共同部署。 |
| `replace_after_backup/<原名>.webp/png` | 原三件套图集。 | 与候选 BIN 共同部署。 |
| `source_patch.json` | 生成候选 BIN 的带 SHA-256 补丁。 | 审计、复现与版本管理。 |
| `validation_report.json` | 候选资源的回读、诊断、计数和代表帧检查。 | 判断是否应进入游戏内测试。 |
| `README_游戏内验证.md` | 替换、备份、截图和恢复说明。 | 人工回归步骤。 |

实验包生成时，工作台会重新打开候选 BIN，重新读取 XML/WebP，并对每个动画的起点、中点和末点生成离线代表帧。它也会检查 BILE 结构、源哈希、图循环、图集绑定以及 `initial_phase` 是否超出真实子动画帧范围。任何结构错误会阻止打包。

## 建议的游戏内回归流程

先在目标设备或模拟器中备份同名三件套，再只替换实验包中的三件套文件。进入能触发该效果、单位或 UI 动作的场景，在修改附近的槽位截图或录屏。若发生加载失败、图像错位、层级错误、闪烁或循环异常，应恢复备份，并保留游戏版本、资源路径、设备信息、候选 ZIP、补丁 JSON 和画面证据。

> 回读验证证明“工作台能重新解析和离线渲染候选资源”；只有目标游戏中的加载和截图回归，才能证明“该版本游戏接受该修改”。

## 当前边界

实验包不创建新元素、帧、轨道或通道，不重排 BRTS，也不修改未经实证的 `playback_mode`。它是安全地测试**已有结构中的保守字段变化**的工作流，而不是完整 BILE 重建器。
