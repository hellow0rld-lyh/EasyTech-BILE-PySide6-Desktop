# EasyTech 动画瑞士军刀：能力地图

**版本：2026-08-22；目的：让每一条格式支线的实际能力、缺口和下一步可验证目标一目了然。**

本项目不是把不同年代的 `.bin` 强行装进同一个“万能格式”里，而是把它们统一接入同一套专业工作台：资源发现、严格读取、图集关联、静态与时间线审阅、机器可读中转、受限编辑、候选验证和游戏内回归。每一格只有在对应证据链已闭合时才标记为“可用”。

> **读到二进制不等于能编辑；离线预览不等于游戏内播放；能导出 JSON 不等于可安全写回。** 本地图把这三类能力明确分开。

## 1. 当前总体能力矩阵

| 能力层 | BILE v2（将1 / 世2 / 欧3） | BILE v3/v4（世3 / 欧4 / 将3 / 欧6 / 世4） | 欧7 Spine 3.8.99 | 征2 Spine 4.1.x |
|---|---|---|---|---|
| 格式分流与版本识别 | **可用**：五节 BILE；55 个样本验证可变 `track_count`。 | **可用**：六块 BILE；跨游戏测试覆盖。 | **可用**：212 / 212 标准 `string hash → version`。 | **可用**：468 / 468 标准 `long hash → version`。 |
| 完整静态结构读取 | **可用**：BELE/BMRF/BYAL/BMTI/BRTS。 | **可用**：BELE/BXDI/BMRF/BYAL/BMTI/BRTS。 | **可用**：header、strings、bones、slots、constraints、skins、attachments 至 skins 结束。 | **可用**：同等静态区，处理 4.1 long hash 与 sequence 元数据。 |
| 动画时间线读取 | **可用**：BMRF/BELE 时间线、嵌套 reference 时钟。 | **可用**：同上。 | **未解码**：events/animations 尾部。 | **未解码**：events/animations 尾部。 |
| 图集关联与局部预览 | **可用**：XML + PNG/WebP。 | **可用**：XML + PNG/WebP。 | **可用**：传统 `xy/size/orig/offset` ATLAS 区域预览。 | **可用**：`bounds/offsets/rotate` ATLAS 区域预览。 |

| 专业审阅 | **可用**：导航、时间线、Track、BELE 复用取证、变更账本。 | **可用**：同左。 | **部分可用**：骨骼/插槽/皮肤/图集区域/静态档案。 | **部分可用**：同左。 |

| 游戏内候选/回归包 | **只读取证**。 | **可用**：保守候选 BIN 与回归案例。 | **未开始**。 | **未开始**。 |

## 2. 当前工作台能实际做什么

BILE 工作区已经是“可完成严肃实验”的专业工具：可以从同名图片、XML 和 BIN 组成的三件套加载动画，定位 Track/BELE、预览槽位、导出序列、导出静态影响范围、在内存暂存中编辑已验证字段、生成候选差异与实验包，并用 SHA-256、完整重解析和回归清单约束写回。v2 虽然现在已经能读取早期零轨/多轨帧变体，但仍然不允许写回。

欧7与征2已经进入同一个 Ribbon/Dock 工作台，但当前提供的是 **Spine 静态资源审阅模式**：打开同名 `.bin + .atlas + 图片页` 后，可检查版本、骨骼、插槽、约束数、皮肤、区域附件以及未解码动画尾部；资源浏览器选择图集区域会在中央画布显示真实裁切结果；也可导出带 SHA-256、静态结构和明确 `writeback=forbidden` 标记的 JSON 档案。

## 3. 不能假装已经做到什么

| 不能说“已支持”的能力 | 原因 | 正确的完成门槛 |
|---|---|---|
| Spine 动画播放 | 静态骨架后面的 events/animations 仍未按 3.8/4.1 版本规则解码。 | 动画段累计消费为零、每类 timeline 的索引/帧数/曲线均通过真实样本回归，并能生成与图集一致的只读序列。 |
| Spine AI 造动画 | AI 目前只能消费静态档案，尚无可靠的动作时间线中转模型。 | 先有完整只读 timeline JSON、轨道类型语义与时长；再做“只生成中转提案、不写 BIN”的代码化动作描述。 |
| Spine BIN 重建或写回 | 未验证静态与动画序列的所有重定位、索引、sequence 和 runtime 加载边界。 | 逐类型做“单变量写回 → 官方读取器再读 → 游戏内播放”闭环；在此之前禁止。 |
| BILE 全结构修改 | BILE 的记录增删、字符串/块重排、未知字段和 v2 写回仍没有游戏内实证。 | 对每种结构编辑有独立最小实验、完整重解析、像素/游戏内回归和撤销边界。 |

## 4. 接下来按“大步”推进的路线

| 优先级 | 大步目标 | 直接产物 | 通过标准 |
|---:|---|---|---|
| 1 | 欧7 Spine 3.8 动画段全读取 | 动画名、时长、slot/bone/constraint/deform/draw-order/event 时间线档案。 | 212 个样本的 animations 段全部累计消费，零越界，未识别类型严格拒绝。 |
| 2 | 征2 Spine 4.1 动画段全读取 | 版本化 4.1 时间线档案，含新 RGBA/RGB/sequence 类型分流。 | 468 个样本按各 4.1 子版本完成累计消费与回归。 |
| 3 | 新引擎只读序列预览 | 静态 pose + 首批 bone/slot timeline 的画布预览与导出序列。 | 与图集区域、骨骼层级、时间范围一致；复杂网格/约束未支持时明确降级。 |
| 4 | 统一代码化中转 | `Motion Patch DSL`：先描述、验证与可视化，不直接写 BIN。 | 每条提案可静态校验、逐帧预览、导出证据，并保留源哈希绑定。 |
| 5 | 受限写回研究 | 仅对一类经验证 Spine 或 BILE timeline 建立可撤销实验。 | 官方/自有读取回读、二进制最小差异、游戏内回归均通过。 |

## 5. 你现在需要知道的一句话

**BILE 已经是“有保守编辑能力的专业工作台”；欧7和征2已经是“全量静态可读、局部真实预览、等待动画时间线解码的新引擎工作区”。** 接下来不再围绕旧 BILE 的微小字段打转，而是先把两套 Spine 的 animations 段完整吃透，才能让“AI 用代码造动画”和未来更广的编辑真正有地基。
